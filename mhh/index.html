A single storey mental health unit with a basement, walkway and plant roof in New South Wales, supplied as a training dataset of seven discipline models. I took the set from unloaded links with broken paths to an ISO 19650 named federation, ran a ten test clash matrix over four runs, and closed with 94 owned issues, two RFIs to the engineers, a BCF package, a coordinated services sheet and a shared package in Autodesk Construction Cloud.

Model federation

Federation of seven discipline models under ISO 19650 naming

7→1
discipline models federated on one origin into MHH-MEJ-ZZ-ZZ-M3-Z-0001.nwf
▶ Watch this step in Revit · 1:31

01What was wrong

The dataset arrived as a workshared architectural host with seven unloaded links, each pointing at an absolute path on someone else's computer, under course file names that said nothing about discipline or status.

02What I decided

Work on copies and never overwrite received information. Each model was saved as a compacted copy under an ISO 19650 container name with role codes A, S, M, E, F and P, and every link was repointed. Before federating I checked placement: all links sit at the host origin with zero rotation, and Basement 64.90, Ground 70.00, Ceiling 72.70, Walkway 73.40 and Roof 77.00 match in every model.

03What changed

Seven NWC caches named to the same convention, so every object in Navisworks traces back to its Revit source. The first pass came out light: the electrical cache was 0.2 MB with 1,374 light fittings in the model, because the export view had 30 categories switched off. Caught, fixed and re-exported before any clash test ran.

04What I would do next

Move the set to shared coordinates from the survey point before it leaves the training environment. Origin to origin only holds while every author starts at the same point.

Clash test matrix

Ten clash tests set by discipline pair and services precedence

1,123
raw clashes from Run 1, before any triage

01What was wrong

A catch all MEP v MEP test floods results with duplicates and gives every clash two possible owners, so nobody acts.

02What I decided

One discipline pair per test, so each clash lands with one owner. Precedence runs structure first, then gravity drainage because falls fix its route, then large ductwork, pressure pipework, sprinklers and finally containment. Tolerance follows the trade: 25 mm for duct against steel, 15 mm for pipework, 10 mm at the ceiling, and a 50 mm clearance test for trays near water. Light fittings were left out of the ceiling test because recessed lights sit in the ceiling by design.

03What changed

Run 1 returned 1,123 clashes, and 836 of them (75 percent) sat in the three structure tests. That pattern pointed at the selection sets rather than the design, which the next page unpicks. A zero in T05 was tested before it was trusted: temporary copies at 0 mm hard and 50 mm clearance returned 0 and 1, so the zero is real.

04What I would do next

T10, structure against trays, was added after the Run 2 review exposed a gap. On the next project it goes into the matrix from day one.

03 / 07MHH-MEJ-ZZ-ZZ-M3-Z-0001.nwf  ·  Runs 1 and 2  ·  21 to 22 Nov 2026
Clash filtering

Removal of false clashes from the first clash run

1,123→370
raw clashes in Run 1, live clashes after the selection sets were rebuilt

01What was wrong

75 percent of Run 1 sat in the structure tests, and T02 alone reported 539. Numbers that lopsided usually mean the selection is wrong, not the design.

02What I decided

Interrogate the results by category before touching any geometry. The whole file sets for structure, drainage and sprinklers had pulled in Revit room volumes (119 clashes in T02 and 119 in T03), 361 slab sleeves and 76 wall penetrations designed to sit inside the slab, plus analytical panels, topography and masses. Not one sprinkler clashed with structure. I rebuilt STR, DRAIN and SPRK to physical categories only and kept the originals as WholeFile_Run1 sets for the audit trail. Nothing was hidden or approved to make the number fall.

03What changed

T02 fell from 539 to 1, T03 from 154 to 0 and T04 from 17 to 0. Run 2 held 370 live clashes, grouped into 138 issues: an 88 percent reduction from Run 1, with every removal explained.

04What I would do next

Make the physical category rule part of the search set template, so the next federation starts at Run 2 quality.

Clash triage

Triage of 430 live clashes into 94 owned issues

430→94
live clashes in Run 4, grouped into owned issues across 10 tests

01What was wrong

With the noise filtered out, Run 4 still held 430 live clashes. A flat list that long gets opened once in a meeting and then nobody acts on it.

02What I decided

Group clashes by system pair and location, then give each group a single owner using services precedence: structure stays put, ducts take priority over trays. Priority follows penetration depth, High above 100 mm and Medium from 25 to 100 mm. When the fix is a design decision, it goes to the engineer as an RFI instead of being modelled away.

03What changed

94 issues, 41 of them High. Two RFIs carry 71 issues between them. Every line has an owner, an action and a due date in the issue log and the BCF file.

05 / 07MHH-MEJ-ZZ-ZZ-M3-Z-0001.nwf  ·  Run 4  ·  22 to 23 Nov 2026
Issues and RFIs

121 duct clashes classified into four issue types with owners

121→4
T01 structure v duct clashes, split into owner classes

01What was wrong

T01 looked like one problem, ducts through beams. Sent that way, all 121 would have gone to the structural engineer, who would have returned most of them.

02What I decided

Break T01 down by steel member, duct size and system. Roof and deck openings are intentional, so the architect confirms upstands. A duct deeper than its beam cannot pass through it, so mechanical drops or reroutes. Bracing and posts cannot be penetrated. Only ten small ducts, under roughly 60 percent of beam depth, went to structural as web opening candidates, with that rule of thumb stated and the real limit left to the engineer.

03What changed

Structural receives 10 clashes in RFI 001 instead of 121. RFI 002 asks the electrical engineer to choose a tray route through the ceiling void, settling 69 linked issues with one answer. The single T02 clash turned out to be a sanitary riser fitting 20 mm into a 100 mm slab: an alignment fix for the drainage modeller, not a structural question.

04What I would do next

When RFI 001 returns opening sizes, model the openings in the structural model and rerun T01 to confirm all ten close.

Run history and reporting

Run comparison and coordination reporting

−78+104
clashes cleared and created by the Run 3 tray lift

01What was wrong

In Run 3 the electrical trays were lifted 150 to 250 mm to clear the ceiling zone, and T08 fell by 78. Checked against T08 alone, it looked like a fix.

02What I decided

Every geometric change is rerun against the whole matrix before it is accepted. The rerun showed 78 trays driven into steel beams in T10, up to 477 mm deep, and 26 into ductwork in T07. The void between ceiling and beam soffit cannot hold the trays at their width and route, so it is a design decision for the electrical engineer, not a modeller's move. I restored the Run 2 electrical model, checked byte for byte with cmp, re-exported and raised RFI 002.

03What changed

Run 4 matched the Run 2 baseline on every test, 430 live clashes, with the lifted model archived for the record. Reporting went out as a custom HTML report with one card per issue group, an issue log with live summary formulas, a BCF 2.1 package of 94 topics (284 XML files, all parsing cleanly) and a coordinated services sheet framing both RFI zones.

04What I would do next

A services zone study drawn as sections (ceiling level, beam soffit, duct zone) before any tray moves again.

Common data environment

ISO 19650 workflow in Autodesk Construction Cloud

WIP→SHARED
ISO 19650 information states in Autodesk Construction Cloud, captured 23 Nov 2026
▶ Watch this step in Revit · 1:23

01What was wrong

Coordination files on one laptop have no status, no permissions and no audit trail. ISO 19650 expects a common data environment where information moves through WIP, Shared and Published states.

02What I decided

Move the models to the cloud with Collaborate in the cloud, into discipline WIP folders. Apply the ISO 19650 naming template, set folder permissions so each team can only create in its own WIP folder, then let Design Collaboration discover the folders as teams and set up a coordination space with clash detection on.

03What changed

Architectural, Mechanical and Structural run as teams. The architectural model was published as package Architectural (1), for consumption, and shared with every team. The timeline records the exchange, and the Shared folder now holds version 1 of the architectural model.

04What I would do next

Add a one step review and approval so a shared package can move to Published with an A suitability code, and raise the RFI items as ACC Issues pinned to the model.
